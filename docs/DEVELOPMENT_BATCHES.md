# Sunrise PDF Editor — 일괄 개발·검증 운영 방식

- 적용 범위: Work Draft PR #9 위에 작성되는 후속 Draft PR #10
- 최우선: 기존 기능 보존, 개인정보·PDF 바이트 미업로드, OCR 제외
- 원칙: 연관 기능 3~5개를 묶어 개발하고, 묶음 당 한 번의 코드 커밋과 한 번의 전체 품질 검증을 우선한다. 오류 수정 시에만 별도 커밋을 사용한다.

## 선택 검사(개발 중)

`npm run test:admin` — 관리자·통계·홈페이지·공지·문의 계약 검사

`npm run test:batch` — 양식·압축·일괄 처리·품질 검사 계약 검사

`npm run test:editor` — 그 밖의 편집·페이지·북마크 동작 계약 검사

위 명령은 전체 `npm test` 목록에서 그룹 필터로 선택하며, 전체 검사를 대체하지 않는다.

## 작업 묶음 종료 게이트

1. 해당 기능의 단위/계약 검증 및 오류 수정
2. **`npm test` 전체 51개 검사**, `npm run progress:check`, `npm run build` 전부 통과
3. 별도 GitHub Actions Linux Chromium 실제 저장·다운로드·재열기 E2E 통과
4. 관련 기능별 점수와 단계/총괄 진행률 기록, 미검증 상태 유지
5. S0/S1 결함·실기 검증·보안 기능 게이트가 완료되지 않으면 운영 배포 금지

## 개발 진행률 기준

`docs/development-progress.json`이 유일한 점수 기준이며 `docs/DEVELOPMENT_PROGRESS.md`는 자동 생성한다. 구현 40%, 자동 검사 30%, 실사용 검증 20%, 운영 배포 10%를 적용한다. 단계별 가중치는 동일하며 OCR 항목은 제외한다.
