# Sunrise PDF Editor (Web) — DEV5 빠른 개발 배치

## 기준과 적용 범위
- **원본**: R32-DEV4 전체 소스 ZIP (기존 원본은 불변).
- **방식**: DEV5 단일 전체 소스 트리에서 USR-14·15 **3개 기능 확장**을 한 번에 처리.
- **실행 범위**: 소스 작성·제품 메뉴 연결·후속 검증 코드 작성. **npm 설치, 빌드, CI, 테스트 실행, GitHub/Cloudflare 배포는 하지 않음**.
- 기존 `dist/`는 DEV5 신규 소스를 반영하지 않은 구버전 정적 산출물. 실제 사용 전 승인된 빌드와 실기 검증이 필요함.

## USR-14: PDF 암호 보호 및 해제
1. **별도 소유자 암호**를 선택 입력. 지정하지 않으면 Worker 내부 Web Crypto의 난수로 256비트 임의 소유자 암호 생성. 사용자 열기 암호와 소유자 암호를 같게 설정하지 않음. 자동 생성 암호는 사용자에게 반환·저장하지 않으므로 소유자 암호를 별도로 사용할 계획이면 직접 설정해야 함.
2. 편집기 `PDF 암호 해제(실험)` 메뉴와 도구 검색 추가. 암호화 PDF를 편집기에 열지 않고 별도 파일 입력과 비밀번호를 받아 QPDF WebAssembly로 복호화 후 **새 파일**로 다운로드.
3. 입력 파일 20MiB 이하, 암호화 PDF 200쪽 이하, QPDF 지원 형식, HTTPS/localhost, 같은 출처의 QPDF JS/WASM 패키지 필요. 암호 해제 시 사용자 암호 길이 최소 1자(기존 암호이므로 12자 규칙을 강제하지 않음).
4. 복호화 전후 페이지 수와 실제 암호화 여부 확인. 원본 불변, 실패 시 결과 미저장, 취소 시 Worker 종료, 암호·PDF 서버 업로드 및 로컬 스토리지 저장 없음.
5. **미검증**: 암호 보호·해제의 실제 성공, QPDF 버전 API 호환성, 다른 PDF 뷰어에서의 양식·첨부·서명 영향, 고난도 PDF.

## USR-15: 암호화된 RSA PKCS#8 PEM 개인키
1. 기존 PEM RSA-SHA256 CMS/PDF ByteRange 서명 경로 유지. 암호화되지 않은 PKCS#8 외에 **PBES2 + PBKDF2 + AES-256-CBC** 형식의 `ENCRYPTED PRIVATE KEY` PEM 추가.
2. Web Crypto의 PBKDF2/AES-CBC로 개인키를 복호화한 다음 기존 비추출형(`extractable:false`) RSA 키를 임포트. 사용자에게 인증서 파일·개인키 파일·개인키 비밀번호 입력 UI 제공.
3. DER 길이·OID·salt·반복 횟수·IV·키 길이 검증, 지원하지 않는 알고리즘 거부. 비밀번호 및 평문 키 바이트는 가능한 범위에서 조기 제거. JS 문자열 완전 메모리 소거는 보증할 수 없음.
4. **미구현**: P12/PFX 파일, 스마트카드, KISA 공동인증서 저장소 직접 연동, CA 신뢰/폐기 검사, PAdES/LTV, 외부 Adobe 뷰어 서명 검증.
5. **미검증**: 실제 OpenSSL 암호화 PKCS#8 키로 CMS 서명 생성, 다른 PDF 뷰어 수용 및 서명 유효성.

## 기능 현황
- R26 기존 관리기록 사용자 기능 19개 평균 **68.1%**; 관리자 14개 포함 33개 평균 **81.6%**.
- DEV5에서 신규 코드를 구현했더라도 동작 검증 전이므로 완료율은 임의 상승시키지 않음.
- 차기 개발 우선순위: USR-05 한글 CID/복합 폰트 지원을 위한 안전한 서식 처리 설계, USR-16 이미지·표 구조 복원, USR-13 개인정보 누락 위험 관리. USR-14/15의 실제 암호화·서명 검증이 뒤따라야 함.
