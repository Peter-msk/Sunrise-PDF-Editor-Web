# R19 — PDF 일괄 처리의 비동기 취소 경계 강화

- 대상: `src/assets/sunrise-batch-pages.js`, 기능 USR-11(분할·병합), USR-18(저장 안전성).
- 선행: R18의 입력 바이트 수·페이지 내용 스트림 무결성 검증을 유지한다.
- 원인: 기존에는 취소가 파일 읽기/파싱·저장/결과 재열기의 `await` 직후 항상 확인되지 않아, 사용자가 취소한 파일도 남은 고비용 검증으로 진행할 수 있었다.
- 해결: `readSource`의 파일 읽기 직후/파싱 직후, `verifyResult`의 저장 전/직후·출력 재열기 직후/구조 검증 직후, 페이지 복사 이후 취소를 명시 확인한다.
- 취소 신호 시 `AbortError`로 중단한다. 기존 분할 단위 원자성, 병합 전체 원자성, 실패 문서 격리 및 다운로드 차단 계약을 보존한다.
- 새 테스트: `tests/batch-cancel-boundaries.cjs`에서 실제 pdf-lib를 이용해 정상 12쪽 분할·20쪽 병합, 읽기 도중 취소, PDF 파싱 직후 취소, 저장 직후 취소, 결과 재열기 직후 취소를 분할과 병합 모두 확인한다.
- 성능 효과의 범위: 이미 취소한 요청에서 **후속 파싱·재검증을 생략**하는 동작을 증명한다. 메모리 사용량의 절대 상한 또는 대형 PDF 복사/직렬화 자체의 즉시 중단은 이 변경의 범위가 아니다.
- PDF 복사 및 `PDFDocument.save()`처럼 단일 호출 중 차단 불가능한 작업은 여전히 해당 호출 종료 후 취소를 반영한다. 취소 관련 약속을 과장하지 않는다.
- 운영 `main`/Cloudflare/D1은 변경하지 않는다. 단위·브라우저 CI 결과는 해당 PR에서 별도 기록한다.
