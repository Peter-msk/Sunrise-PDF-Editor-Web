# R18 — PDF 일괄 분할·병합 입력/출력 무결성 보강 (USR-11, USR-18)

- 기준 브랜치: `dev/r17-form-save-integrity-20261103`의 검증 완료 커밋 위에서 분기.
- 대상: `src/assets/sunrise-batch-pages.js`.
- 변경 전: 입력은 양수 길이의 바이트 배열인지 검사했으나 파일 메타데이터에 선언된 크기와 직접 비교하지 않았다. 저장 후 출력은 페이지 수, 회전각과 5개 박스의 위치/크기만 대조했다.
- 변경 후 입력: 읽은 바이트 수가 파일의 `size`와 정확하게 일치해야만 PDF를 파싱한다. 불일치 파일은 분할 시 해당 파일만 실패시키며 병합 시 전체 결과를 제공하지 않는다.
- 변경 후 출력: 각 원본 페이지의 `/Contents` 원시 스트림 개수·총 바이트 수·32비트 FNV-1a 지문을 숫자 스냅샷으로 보관한다. 저장 결과를 다시 열고 동일 페이지 지문을 비교한 후에만 분할 또는 병합 결과를 게시한다.
- 기존 구현의 페이지 수/회전/MediaBox/CropBox/BleedBox/TrimBox/ArtBox 검사와 취소·문서별 분할 원자성·병합 전체 원자성은 유지한다.
- 원본 페이지 PDFPage 객체나 PDF 바이트를 추가 보관하지 않아 원본 PDF 컨텍스트 참조 해제 정책을 유지한다.
- 오류 메시지에는 문서 내용이나 입력 데이터가 아닌 고정 사유만 포함한다.
- 신규 실 PDF 엔진 검사 `tests/batch-content-integrity.cjs`: 일반 분할·병합 출력 재열기, 파일 크기 불일치 파일의 독립 격리/병합 원자성, 출력 저장 후 내용 스트림 삭제/추가 변조 주입, 원본 바이트 불변 확인.
- **검증 경계:** FNV-1a는 암호학적 보안 해시가 아니다. PDF 페이지 `/Contents` 스트림 검증이며 PDF 글꼴, 이미지 XObject, 첨부, 모든 PDF 객체 또는 실제 시각 품질 전체 보존을 증명하지 않는다. OCR 제외. 실무 PDF와 실제 모바일 기기는 별도 수용한다.
- 운영 Worker/D1/기존 `main`은 이 개발 PR에서 변경하지 않는다. 수치 진행률은 신규 자동검증 완료와 실무 수용을 구분하여 관리한다.
