# Sunrise PDF Editor(Web) R32-DEV1 — 미완성 기술 1차 소스 개발

기준은 실제 통합된 `Sunrise-PDF-Editor-Web-R32-integrated`이며 **제품 원본은 변경하지 않고** `R32-DEV1`의 전체 소스 폴더로 독립 복제했습니다.

## 변경 내용

### USR-13: 지정 영역 마스킹 검증 강화
- 기존 `paintVerifiedMask`는 각 사각형의 다섯 표본점만 검사했습니다.
- `verifyFullMaskCoverage`를 추가해 지정 사각형 **모든 픽셀**을 검은색·불투명 상태로 검사합니다.
- `getImageData`를 최대 약 512KiB 단위로 나누어 검사해 대형 영역에서 추가 메모리 사용을 억제합니다.
- 단일 및 다중 페이지 마스킹 출력 모두에서 픽셀 검사 실패 시 결과 PDF를 생성하지 않습니다.
- PDF 출력 재열기 시, 각 페이지에 글꼴 리소스가 남아 있지 않고 **정확히 하나의 이미지 XObject**가 있는지 확인합니다.
- 보안 고지: 자동 개인정보 탐지·누락 검출·모든 자료 완전 삭제의 인증 기능이 아닙니다. 지정한 영역 외 내용은 원본처럼 보일 수 있습니다.

### USR-16: Word 단락·표 구조 추정 기능 신규 추가
- 메뉴 `도구·추출 → 변환/추출 → Word 단락·표 구조 추정 (실험 기능)`을 추가했습니다.
- PDF.js 텍스트 레이어에 있는 좌표·글자 크기·글꼴 이름을 읽어 제목 수준, 글자 크기, 굵기·기울임 단서, 들여쓰기, 가운데 정렬 등을 추정하는 `docxLayout` 함수가 추가됐습니다.
- 3줄 이상이고 시작 좌표가 일정한 2~8개 열의 텍스트 줄은 편집 가능한 Word `<w:tbl>`로 변환합니다.
- Word 스타일 정의 `word/styles.xml`과 연관 관계 XML을 포함해 DOCX의 구조를 구성했습니다.
- 기존 텍스트 전용 Word / Excel 텍스트 / Excel 열 추정은 변경하지 않았습니다.
- 한 페이지가 90° 회전, 수직쓰기, 기하 정보가 없거나 텍스트가 겹치는 경우 임의 복원 대신 오류를 출력합니다. 기존 텍스트 전용 Word 기능을 대안으로 제공합니다.
- 보안 고지: 서식 추정이므로 PDF 원본의 이미지·도형·셀 병합·완벽한 읽기 순서·정확한 글꼴을 복원하는 기능은 아닙니다.

## 변경된 실제 제품 파일
- `src/editor/index.html` — 사용자 메뉴 및 새로운 DOCX 선택, 마스킹 보안 안내
- `src/assets/sunrise-office-export.js` — Word 구조 추정 엔진
- `src/assets/sunrise-special-pdf.js` — 픽셀 전체 검사 및 이미지 전용 출력 구조 검사

## 회귀 코드 작성 (실행하지 않음)
- `tests/office-text-export.cjs` — Word 표 구조·회전 문서 거부·메뉴 연결
- `tests/special-pdf-guard.cjs` — 단일 마스크 전수 픽셀 검사와 모의 렌더러 보완
- `tests/multipage-mask-audit.cjs` — 다중 마스크 모의 렌더러, 내부 미도포 픽셀 검출 사례

## 미구현 또는 검증 대기
- **USR-14**: 웹 브라우저에서 호환되는 PDF AES 암호 보호 기능 없음. 기존 Node/QPDF 로컬 도구와 별개입니다.
- **USR-15**: 인증서·CMS 서명을 포함하는 실제 PDF 디지털 서명 없음. 기존 시각 서명만 유지합니다.
- **USR-05**: 한글·CID·복합 폰트 원문 직접 수정은 아직 미구현입니다.
- **USR-13**: 개인정보 자동 탐지는 없으며 기밀정보 완전 삭제 보증을 주장하지 않습니다.
- **USR-16**: OCR, 이미지·도형 및 정확한 레이아웃/셀 병합 복원은 미구현입니다.

**중요:** 소스코드 작성은 완료했지만 테스트, 실행, 빌드, CI, 사용자 실기, GitHub 반영 및 Cloudflare 배포를 시행하지 않았습니다. `dist/`는 이전 빌드 결과이므로 이번 개발 내용을 포함하지 않습니다.

기능별 기존 관리 구현률은 `docs/development-progress.json`의 **USR-13 47%, USR-16 62%, USR-14 22%, USR-15 30%**를 그대로 보존했습니다. 코드 추가만으로 검증 완료율을 임의로 상향하지 않았습니다.
