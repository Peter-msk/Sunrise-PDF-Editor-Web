## 이번에 수정한 검사 문제

- 오래된 SQL 대체 구현에 새 D1 batch/보존 실행 기록이 없어 실패하던 검사를 전체 최신 스키마의 실제 SQLite와 트랜잭션으로 보완했다.
- 저장 준비 검사에 추가된 Worker 버전 열과 응답 계약을 반영했다. 중복 시도·잘못된 재시도 링크·보존 연쇄 삭제 검사는 유지했다.
- 알림 배열을 특정 소스 문자열로 비교하던 검사를 실제 화면 함수 실행으로 바꿨다. 다섯 알림 종류의 중복 제거·텍스트 출력·빈 상태를 확인한다.
- 별도로 추출한 PDF 함수를 실행하는 13개 검사에 실제 `beginOperationMetric` 함수 경계를 연결했다. PDF 보존·실패·취소 관련 기존 assertion을 유지한다.
- 실제 SQLite 기반 새 검사로 준비 상태/누락 열, 세션 유휴 만료/전체 폐기, 비밀번호 변경, 보안 이력의 민감정보 미포함, 예약 정리 실행 상태를 확인했다.
- 관리자 Chromium fixture에 수정 버전·전체 스키마·최신 응답 형식을 반영하고 별도 실행 명령 `npm run test:admin:browser`를 등록했다.

로컬 Chromium 실행 파일이 없어 설치를 시도했으나 다운로드 주소에서 ZIP 대신 Site Unavailable HTML이 반환됐다. 검사를 통과한 것으로 추정하지 않고, 배포 단계가 없는 기존 GitHub 검증 워크플로우에서 실제 Chromium 검증을 수행했다.

## Windows Chrome/Edge 및 운영 준비 후속 검증

검증 커밋: bba0b497c8a9dd9382d113acc760ac285308aa15. [GitHub Actions 41277738101](https://github.com/Peter-msk/Sunrise-PDF-Editor-Web/actions/runs/41277738101)의 Node/빌드, Linux Chromium, Windows Chrome, Windows Edge 네 작업이 모두 성공했다.

| 실행 환경 | 실제 브라우저 버전 | 결과 |
|---|---|---|
| Windows 2025 runner / Chrome | 156.0.8078.48 | 관리자 대시보드·문의/게시물/CSV·HTTPS 인증·PDF 저장/재열기 4개 통과 |
| Windows 2025 runner / Edge | 155.0.4283.62 | 같은 4개 흐름 통과 |

Windows headless CI의 실제 설치된 브라우저로 실행했다. 사용자의 업무 PC, 조직 브라우저 정책, 모바일, 모든 실무 PDF나 장시간 사용을 검증한 것은 아니다.

발견·수정한 실제 결함:

- Windows 체크아웃의 CRLF 때문에 릴리스 빌드가 편집기 스크립트 경계를 못 찾던 문제를 수정했다. 실제 빌드를 LF/CRLF/CR 입력으로 실행해 출력 동작과 원본 보존을 확인했다.
- D1 백업 목적지의 상위 심볼릭 링크가 저장소를 가리키는 경우를 실제 경로로 판정해 차단했다.
- 격리 복원 전 빈 DB 판정에서 null·빈 문자열·실패 응답이 빈 DB로 오인되지 않도록 성공한 단일 정수 결과를 요구한다.

합성 Wrangler 프로세스와 실제 Python SQLite 백업/격리 복원을 Linux 및 Windows에서 실행했다. 덮어쓰기 방지·실패 파일 정리·내용 미출력·시험 DB 이름 제한을 확인했다. 실제 원격 D1 내보내기/복원을 실행한 것은 아니다.

서명 배포 보고는 실제 Worker 코드와 SQLite에서 본문 변조·잘못된 서명·시각 범위·중복/역순·입력 크기·권한 없는 조회·DB 오류 정보 미노출을 확인했다. 실제 production 파이프라인 연결은 미완료다.

실제 운영 D1과 Worker 설정은 구조/바인딩 이름·종류만 읽어 확인했다. 새 테이블 5개, 기존 열 5개 및 배포 보고/버전 메타데이터 설정 차이가 남아 있다. 구체적인 차이는 `PRODUCTION_SCHEMA_REVIEW.md`를 따른다. 운영 데이터 내용·비밀값을 조회하지 않았고 변경도 하지 않았다.

후속 복원 응답 검사에는 명시적 success=true가 없는 결과와 잘못된 JSON도 추가했다. 외부 응답의 JSON 해석 오류는 고정 메시지로 표시해 원문 일부가 오류 메시지에 포함되지 않도록 했다.

최종 후속 검사에서 문의 검색 E2E가 기존 목록의 행을 검색 완료로 잘못 간주하던 대기 조건을 수정했다. 검색 결과 1건과 해당 문의 행이 함께 갱신된 뒤 동일 assertion을 실행한다. 타임아웃이나 검증 조건을 완화하지 않았다.
