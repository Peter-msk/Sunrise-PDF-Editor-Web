# USR-07 — 기존 PDF 표준 주석 편집/삭제 (개발용 Draft)

## 목적 및 사용자 진입
- 브라우저 편집기 상단 **편집·주석 → 주석 작성 → 원본 PDF 주석 관리**.
- 현재 페이지에 이미 존재하는 **/Text(메모)** 및 **/Highlight(형광펜)** 주석의 `/Contents` 문구 수정 또는 주석 목록에서 참조 제거.
- 새 내용은 PDF 표준 Unicode `PDFHexString.fromText`로 저장하고 PDF 라이브러리로 재직렬화한 뒤, PDF.js 재열기·페이지 구조 검증을 수행한다.
- 원본 파일은 변경하지 않는다. 편집기에서 Undo 후 **다른 이름으로 저장**하여 별도 PDF로 내려받는다.

## 보안·지원 범위
- **단순 Text/Highlight만** 지원하며 형광펜 하이라이트 위치·QuadPoints·색상/외양(AP) 변경은 미지원.
- 전자서명 가능 문서(인증 Perms, ByteRange 표식)와 AcroForm 문서, 연결 답글·팝업, 잠긴 주석, 지원 외 객체 및 과도한 주석 참조 수는 거부.
- 이번 삭제는 **페이지에서 주석 참조를 제거하는 동작**이며, 숨겨진 객체·증분 업데이트·첨부파일에 남은 개인정보까지 정리하는 민감정보 **완전 삭제(redaction)가 아니다**.
- 새 코드가 모든 PDF 표준 주석 유형, 모든 PDF 뷰어의 서명 유효성, 1,000쪽 이상의 업무문서 적합성 또는 인증 보안을 보장하지 않는다.
- 개인 PDF 원문은 서버로 업로드하지 않는다. OCR 제외.

## 검증
- 계약 검사: `node tests/native-annotation-edit.cjs`.
- 테스트는 한글/Unicode 문구 수정, 삭제, 표준 타 유형·다른 페이지 보존, 실제 PDF 바이트 재저장·재열기, 원본 바이트 불변 및 서명·양식·참조 관계·잠금 차단을 다룬다.
- 공통 `npm test` 및 Linux Chromium, Windows Chrome/Edge CI 결과는 PR #28의 워크플로를 따른다.
- 실제 UI 클릭→저장→서드파티 뷰어 재열기 E2E와 다양한 스캔/전자서명 문서의 현장 수용검사는 별도 필요하다.
