# 기능 실패 진단 및 문서 열기 보완

## 확인한 기존 기록

운영 DB의 문서 열기 집계는 2026-11-02 4건이다. 저장 필드는 day/feature/count뿐이며 단계·원인·브라우저·버전·문서 정보는 없다. 2026-11-03 별도 작업 통계의 open 성공 4건은 다른 날짜의 기록이므로 같은 4건으로 연결할 수 없다. 기존 실패 원인을 특정했다고 주장하지 않는다.

기존 클릭/토스트 추정 수집은 병합을 문서 열기로 분류하고 경고나 무관한 런타임 오류를 직전 클릭 기능으로 집계할 수 있었다. 또한 파일 읽기는 open 작업 밖에 있었고 첫 화면 렌더링 실패를 삼켜 작업이 성공으로 끝날 수 있었다. 관리자 결과 표에는 새 도구의 라벨이 누락되어 전체 조회를 중단할 수 있었다.

## 변경 계약

- 파일 읽기부터 한 open 작업으로 측정한다. 입력 검증·파일 읽기·헤더·편집용 구조·PDF.js·페이지 정보·첫 화면 표시를 고정 코드로 구분한다.
- 첫 화면 실패는 실패로 기록하고 새 탭/최근 파일 게시를 되돌린다. 기존 문서는 유지하고 새 reader를 정리한다. 엔진 초기화 Promise를 기다린다.
- PDF.js의 초기 헤더 탐색 범위 안에 있는 BOM/앞부분 공백 등을 허용한다. 모든 손상 PDF를 복구한다는 뜻은 아니다.
- 새 구조화 실패는 같은 작업에서 한 번만 반영한다. 상태 변경·진단·세션 오류·집계는 D1 batch로 묶어 실패 시 전체 롤백한다. 경고 토스트·취소는 실패 증거로 사용하지 않는다.
- 미처리 런타임 오류는 기타 신호로 구분하고 직전 기능에 연결하지 않는다. 알려진 원문 수정·이미지 추출·양식 일괄 변경 등 누락된 작업 코드와 관리자 라벨을 연결한다.
- 관리자 진단 표/CSV는 기간·Worker 버전·전체/문서 열기 필터를 제공한다. 원인/조사 안내, 분 단위 시각, 입력 경로, 크기/쪽수 구간, 브라우저 종류, 화면 진단 빌드를 제공한다.
- 원인 코드는 허용 목록만 저장한다. PDF 내용·파일명·검색어·오류 전문·스택·전체 User-Agent를 저장하지 않는다. 기존 4건은 원인 미확인 집계로 보존하며 새 진단과 합산하지 않는다.
- 일부 작업의 상세 원인은 아직 operation_failed로 표시한다. 임의 추측으로 원인명을 만들지 않는다. 네트워크/수집 차단·세션당 일일 40건 제한으로 누락될 수 있다.

## 배포 및 보존

`migrations/0017_operation_diagnostics.sql`을 원격에 적용한 뒤 새 코드를 배포한다. 기존 18개 테이블은 변경하지 않고 analytics_diagnostics만 추가한다. 운영 적용 전 비공개 전체 스냅샷과 오프라인 복원 검사를 수행한다. 신규 진단은 작업/익명 세션 정리의 FK cascade로 14일 기준 정리된다. 과거 집계는 새 진단으로 변조하지 않는다.

확인 명령: `npm run test:diagnostics`, `npm test`, `npm run build`, `npm run dist:verify`. 실행 중인 운영 사이트에 합성 실패를 전송해 실제 오류 통계를 오염시키지 않는다. 브라우저 운영 예제는 telemetry를 가로채 전송 페이로드만 확인한다.

원인 구분은 재현을 돕는 진단이다. read_failed만으로 메모리 부족을 확정하거나 pdf_parse_failed만으로 원본 손상을 확정하지 않는다. 최초 4건의 정확한 원인은 당시 개별 기록이 없어 복원 불가다.
