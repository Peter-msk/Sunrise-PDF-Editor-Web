## 정확한 진행률의 의미

- 사용자 기능 **19개 기존 코드 구현률 평균: 68.1%** (R26 관리 기록, DEV1~DEV4 미검증 변경 미가산).

## DEV3에서 실제 변경된 개발 코드

- `src/assets/sunrise-pdf-cms.js`: RSA/X.509 PEM과 CMS DER 생성, PDF `/Sig` 필드 및 `ByteRange` 서명 생성 로직 신규.
- `src/editor/index.html`: 인증서 서명 메뉴와 파일 입력·서명·원본 보존·분리형 출력 연결.
- `src/assets/sunrise-tool-hub.js`: 도구 검색·실행 연결.
- `scripts/build-release.cjs`: 향후 승인된 빌드에 신규 엔진 포함하도록 사전 등록.
- `tests/cms-signature-practical.cjs`: 향후 OpenSSL 외부 검증 코드 작성(실행 안 함).

## DEV2에서 실제 변경된 개발 코드

- `src/assets/sunrise-special-pdf.js`: WinAnsi 코드포인트→단일 바이트 대응, PDF Tj의 hex/이스케이프 리터럴 처리, 서명 ByteRange 간접객체 방어, 일괄 변경 입력값 동일 인코딩 길이 검사.
- `src/editor/index.html`: 원문 단일·일괄 수정 후보 탐색과 문구 검증·사용자 제한 고지를 변경된 WinAnsi 엔진과 일치시킴.
- `src/assets/sunrise-office-export.js`: DEV1 DOCX 구조 추정에 PDF별 용지 크기·방향·추정 여백·문단 간격을 반영하고, 혼합 페이지 크기도 Word 섹션으로 구분. 지원 범위 외 용지는 중단.
- `tests/dev2-winansi-source-contract.cjs`, `tests/dev2-office-section-contract.cjs`: 향후 실행용 회귀 사례 소스만 작성. **아직 실행하지 않음.**

## 안전·호환성 한계

1. USR-05 WinAnsi 지원은 PDF **표준 Type1 글꼴**과 PDF 파일에 명시된 `/WinAnsiEncoding`으로 한정. 한글 Unicode/CID, 임베디드 폰트, 실제 글자 너비 차이로 인한 레이아웃 변화는 미해결. 원문 수정은 민감정보 완전 삭제가 아님.
2. USR-16 Word 출력의 여백·문단은 추정값이며 복잡한 PDF 서식의 완전 복원을 주장하지 않음. 기존 단순 DOCX, XLSX 경로는 보존.
3. USR-14 웹 암호화는 DEV4에서 **소스 연결을 작성했으나 WASM 미설치·미검증**. USR-15는 **서명 코드 작성 완료 / 검증 및 확장 미완료**. 단순 버튼이나 비표준 암호문을 암호화 PDF로 표시하지 않음.
4. OCR 제외. `dist/`는 기존 산출물이고 DEV2를 반영한 빌드 결과가 아님.
5. 테스트·빌드·실기·원격 GitHub/Cloudflare 실행하지 않음.

## DEV3 구현 범위와 진행률 해석

USR-15의 기존 코드 구현률 **30%는 R26 관리 수치**입니다. DEV3는 코드상 암호학적 서명 경로를 추가했지만 외부 도구·PDF 뷰어에서 검증하지 않았으므로 새 숫자 구현률을 정하지 않습니다. 인증서 신뢰 및 폐기, PAdES, PKCS#12가 여전히 미구현이므로 USR-15 전체 개발 완료가 아닙니다.
