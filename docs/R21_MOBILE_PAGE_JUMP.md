# R21 · USR-19 모바일 페이지 직접 이동

## 확정 v1.2 범위
USR-19 모바일 UX 65% 구현 기준 위에서, 하단 페이지 표시를 터치 가능한 페이지 바로 이동 버튼으로 변경한다. 모바일의 이전·다음 버튼, 파일 열기·저장·병합 흐름은 유지한다.

## 구현
- 하단 `mobPageIndicator`를 40px 이상 터치 목표를 가진 버튼으로 전환하고 현재/전체 쪽과 접근성 레이블을 유지한다.
- 열린 PDF가 없거나 문서 작업이 진행 중일 때 직접 이동 버튼을 비활성화한다.
- 버튼 터치 → 페이지 번호 입력 모달. 숫자 키패드·최솟값·최댓값, 확인·취소·Enter를 지원한다.
- 기존 데스크톱 `applyPageJump`의 1부터 전체 쪽까지 정수 검사 및 페이지 변경·현재 선택 유지·렌더 경로를 재사용한다.
- 잘못된 페이지 번호는 변경을 거부하고 대화상자를 유지한다. 모달을 여는 동안 문서가 변경되거나 바빠지면 이전 문서를 변경하지 않는다.
- 원본 PDF 바이트, 책갈피, PDF 페이지 수, 문서 저장·다운로드 경로에 변화를 주지 않는다.

## 검증 범위
기존 `tests/browser-save-reopen.cjs` 모바일 터치 실브라우저 경로에 PDF 미개방 시 비활성화, 390px 화면 폭, 범위 오류, Enter 정상 이동, 취소 시 원위치, 버튼 이동, 기존 파일 메뉴 저장·재열기 회귀를 추가. Linux Chromium 및 Windows Chrome·Edge CI 실행의 합격 결과로 판단한다. 실제 Android/iOS 기기·외부 고객 PDF 수용은 별개다.

## 운영
기준 R20 브랜치 위의 격리 R21 PR. `main`, Cloudflare Worker, 운영 D1은 변경하지 않는다. 수치 진행률은 통과 증빙을 확인한 후 구현·자동검증만 평가한다.
