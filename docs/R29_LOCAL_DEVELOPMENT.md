# Sunrise PDF Editor(Web) — R29 로컬 기능 개발 명세

**기준:** R26 개발 코드의 제한적인 USR-05 편집 엔진 + R27/R28 로컬 기능 추가. **상태:** 소스 작성본 / 미실행 / 사용자 실기검증 대기.

## R29 기능 묶음 — 코드 작성 범위

1. **PDF 원문 후보 자동 수집:** 사용자가 입력한 1~전체 페이지 번호의 PDF.js 텍스트 레이어에서 ASCII 1~120자, 동일 문구가 한 번만 나타나는 후보를 최대 100개 로컬로 표시. 후보가 실제 PDF 내용 스트림에서 수정 가능한지는 *적용 때* 기존 엔진이 별도 판정.
2. **후보에서 수정표에 직접 추가:** 후보와 같은 길이의 수정문을 입력하면 `페이지번호<TAB>원문<TAB>수정문` 행 생성. 기존 1~8건, 중복·충돌, 5,000자 입력 제한과 동일한 파서 적용. 문서나 페이지가 달라지면 오래된 후보를 적용하지 않음.
3. **로컬 TSV 가져오기:** 컴퓨터의 `.tsv`/`.txt`(5,000바이트 이하) 파일을 브라우저에서 읽어 정규화·재검증 후 수정 계획에 반영. 네트워크 업로드 없음.
4. **로컬 TSV 저장:** 검증된 수정 계획을 표준 탭·줄바꿈 형식으로 직렬화하여 로컬 다운로드. 원문이 파일에 포함될 수 있으므로 파일 관리 주의 문구 표시.
5. **기존 R27/R28 기능 통합:** 일괄 8건, PDF.js 문구 일치 미리보기, 변경 시 검토 무효화, 일괄 적용 및 Undo 1회, 실패 시 전체 미적용, 20/40 MiB 원본/중간 제한을 보존.

## 보안/지원 범위

- **지원:** 표준 Base14/Type1, 한 개의 `Tj` 텍스트 명령, ASCII 1~120자, 변경 전후 같은 길이, 서명·양식 등 제외, 합성/일부 단순 PDF.
- **미지원:** 한글 직접 원문 편집, 임베디드 글꼴, 복합 `TJ`, 길이 변경, 완전 삭제 인증, 인증서 전자서명, OCR.
- **실기 미검증:** 추가한 후보 수집 UI, TSV 가져오기·다운로드, 전체 원문 수정 워크플로, 실제 고객 PDF.
- 테스트 코드는 작성만 했으며 실행하지 않음. 코드 파일 작성과 기능 PASS는 다름.

## 향후 실기검증 단계(별도 사용자 명령)

1. R26 기준 PC 로컬 저장소에 `apply_r29_local.py --repo "<경로>"` 적용. 프로젝트 밖 백업 생성.
2. 로컬 개발용 웹 서버에서 2쪽 표준 Helvetica 텍스트 PDF 열기(로컬 서버/브라우저만 사용).
3. 원문 후보 읽기 → 후보 선택·수정문 입력 → 목록에 추가 → TSV 저장 → 목록 비우고 TSV 가져오기 → 미리보기 → 전체 적용.
4. 저장 및 재열기에서 원문 검색·복사 일치, 다른 페이지·일치 실패·중복·취소 및 Undo 확인.
5. 한글·양식·서명·특수 PDF는 수정하지 않고 명확히 거부되는지 확인.

*GitHub/Cloudflare/클라우드 빌드/CI 및 자동검증 실행은 사용자가 명령할 때만 수행한다.*
