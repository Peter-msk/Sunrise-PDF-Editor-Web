# R22 — USR-09: 웹 PDF 압축 JPEG 무결성 및 실측 품질 회귀

## 기준
- 확정 계획: v1.2 / USR-09 PDF 압축, OCR 제외.
- 부모: R21 개발 브랜치. 운영 `main`, Cloudflare Worker/D1 미변경.
- 실제 고객 문서·iOS/Android 기기 수용 및 정식 운영 배포를 완료한 것으로 간주하지 않는다.

## 확인된 저장 위험 및 수정
기존 압축 과정은 브라우저 Canvas가 만든 JPEG의 바이트 수가 원본보다 작으면 PDF 이미지 XObject에 직접 삽입했다. PDF는 이미지 바이트가 손상되더라도 **문서 파서의 페이지 수 검사만 통과할 수 있어** 해당 이미지가 나중에 깨질 위험이 있었다.

R22는 `src/editor/index.html`의 `compressPdfImages`에서 **재인코딩된 JPEG 파일 자체**를 PDF-lib JPEG 파서로 검증한다. 이미지의 선언된 폭·높이 및 `DeviceRGB` 색상 형식이 Canvas 출력과 다르면 해당 작업을 오류로 중단한다. 이미지를 변경한 PDF를 사용자에게 게시하지 않는다. 기존 JPEG 품질·긴 변 픽셀 프리셋, 복잡한 마스크 제외, 이미지마다 출력이 작아야 교체, 전체 파일이 작아야 결과 채택 정책을 유지한다.

## 실제 브라우저 회귀검사
`tests/browser-save-reopen.cjs`에 아래 시나리오 추가:
1. 실제 브라우저에서 640×480 임의 패턴 JPEG 생성 후 pdf-lib로 검색 가능한 본문과 함께 PDF 1쪽에 내장.
2. 압축 강도 20/60/90에서 브라우저의 JPEG 인코더를 사용. 저장된 PDF를 재열어 1쪽·제목·검색 가능한 텍스트 보존과 이미지 자원 디코딩 검증.
3. 압축 프리셋별 실측 결과 용량 비교, 강도 90에서 긴 변 320px 다운샘플 확인.
4. 실제 JPG를 디코딩해 80×60 픽셀 표본의 PSNR을 계산. 합성 문서 표본에서 비정상 왜곡을 검사하는 회귀 지표이며 화질 인증이나 작은 글자 가독성을 보장하지 않는다.
5. JPEG 파서가 출력 이미지를 잘못된 크기로 보고하도록 테스트 주입한 뒤, 압축 함수가 결과를 반환하지 않고 실패하는지 검증.
6. 기존 PDF 저장·다운로드·재열기 및 관리자 회귀검사를 그대로 유지.

## 제한사항
- PSNR은 한 가지 임의 패턴 이미지의 80×60 축소 표본 기준이다. 실제 스캔문서·도면의 원문 글자 가독성, 색상 정확도 또는 모든 이미지 형식의 품질을 보증하지 않는다.
- PDF 원문 텍스트와 벡터는 래스터화하지 않는다. 마스크·색상공간·특수 코덱 지원 범위도 변경하지 않는다.
- 개별 PDF 페이지와 이미지의 원본 바이트는 변경하지 않고 새 파일로 저장하는 기존 UI 계약을 보존한다.
- 기존 압축 사용자는 신규 기능 설정을 배울 필요가 없다. 실패할 경우 기존과 같이 다운로드 후보 생성 전에 오류 메시지를 표시한다.
