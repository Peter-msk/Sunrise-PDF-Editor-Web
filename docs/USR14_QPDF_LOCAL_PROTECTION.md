# USR-14 PDF 암호 보호 — 로컬 QPDF AES-256 구현 (개발 단계)

## 실제 구현 범위

- 사용 가능한 범위: QPDF 11.7 이상이 설치된 **로컬 PC 명령줄**에서 원본 PDF를 AES-256으로 암호화하여 **별도의** `.pdf` 파일 생성
- 브라우저 편집기에 암호 보호 버튼이 있는 것으로 표시하지 않습니다. 현재 웹 PDF 편집기에는 비밀번호 입력·AES-256 출력 기능을 연결하지 않았습니다.
- 원본 및 암호를 외부 서버에 업로드하지 않습니다. 파일 변경은 사용자의 PC에서 이루어집니다.
- 기존 전자서명·인증서/서명 필드 또는 서명 여부를 확인할 수 없는 PDF는 차단합니다. 전자서명 보존을 보장하지 않습니다.

## 사용 방법

PC에 QPDF 11.7 이상을 먼저 설치하고 `qpdf --version`이 정상인지 확인합니다. Node.js 22가 설치된 프로젝트 폴더에서 실행합니다.

```powershell
node scripts/protect-pdf-local.cjs "C:\Documents\원본.pdf" "C:\Documents\원본_암호보호.pdf"
```

로컬 터미널에서 열기 암호를 두 번 입력하면 입력 문자는 별표로 표시됩니다. 암호는 명령줄·환경변수·로그·파일에 기록하지 않고 QPDF에 표준입력으로 전달합니다. **암호를 잊으면 파일 내용에 접근하지 못할 수 있으므로 별도로 안전하게 관리해야 합니다.**

암호는 UTF-8 기준 12~200바이트, 줄바꿈/NUL 불허. 출력 PDF는 원본과 다른 경로여야 하며 기존 출력 파일을 덮어쓰지 않습니다. 입력·출력 각각 50 MiB 이하입니다.

출력 직전에 다음을 자동 확인합니다: 실제 AES-256 파일 생성, QPDF 암호화 여부 확인, 비밀번호 필요 여부, 올바른 암호로 검사 성공, 틀린 암호로 검사 실패, **암호화 출력의 PDF 페이지 수와 원본 페이지 수 일치**. 페이지 수 확인도 비밀번호를 프로세스 인수에 노출하지 않고 표준입력으로 수행합니다. 모든 검증 통과 전까지 출력 PDF 경로에 최종 결과를 게시하지 않습니다.

페이지 수 검사는 문서 누락을 방지하기 위한 추가 안전장치이며, 모든 페이지 내용·픽셀·메타데이터가 원본과 완전히 동일하다는 인증은 아닙니다. 출력 페이지 수가 다르거나 검사가 실패하면 새 PDF는 게시되지 않습니다.

## 개발 및 검증 근거

- 일반 계약 테스트: `node tests/pdf-encrypt-local-contract.cjs`
- QPDF 실제 AES-256 PDF 테스트: `npm run test:qpdf-real`
- QPDF 통합검증 CI: [USR-14 QPDF test workflow](https://github.com/Peter-msk/Sunrise-PDF-Editor-Web/actions/workflows/usr14-qpdf-real.yml)
- 사용자 웹 편집기의 암호 보호 기능은 **미구현**. 기존 `pdf-lib` 암호화 미지원. 브라우저 WASM QPDF 통합·기능 QA는 별도 개발해야 합니다.

## 안전 및 호환성 주의

- 파일 내용에 `/ByteRange`, PDF `/Perms` 또는 확인 가능한 `/Sig` 필드가 있으면 서명 손상을 막기 위해 거부합니다. 이는 보수적인 사전검사이며 공식 전자서명 유효성 검증은 아닙니다.
- Acrobat, macOS Preview 등 외부 PDF 뷰어 호환성과 업무 PC 수용검사는 별도 필요합니다.
- QPDF의 보호 설정을 뷰어가 모두 강제한다고 보장할 수 없습니다. 이번 구현은 **열기 암호 기반 AES-256**이며 별도의 인쇄·복사 제한은 제공하지 않습니다.
- ZIP/PDF 변환 시 암호를 누설하거나 평문 사본을 무분별하게 생성하지 않도록 출력 경로를 관리해야 합니다.
