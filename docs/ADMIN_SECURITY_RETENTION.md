# Sunrise PDF Editor — 관리자 보안 및 데이터 보존 점검 (ADM-10·11)

## 실제 코드 정책
- 관리자 인증: 관리자 단일 계정, 브라우저 PBKDF2-SHA256 600,000회 + 서버 HMAC 검증값, HttpOnly/Secure/SameSite=Strict __Host 쿠키. 절대 로그인 8시간, 유휴 30분.
- 비밀번호 변경: 현재 비밀번호 검증 후 새 salt로 재파생, 기존 로그인 세션 **전체 폐기**, 본인 및 다른 관리자 브라우저의 접근 차단. Origin 검사·비밀번호 변경 실패 제한 적용.
- 예약 정리(매일 03:00 UTC / KST 정오): 문의와 연관된 상태 변경 이력 **90일 이전 동시 삭제**, 고아 이력 정리, 익명 세션 14일, 문의 전송 제한 기록 2일, 만료/유휴 관리자 세션 및 오래된 로그인 제한 기록 정리.
- 단순 집계 `analytics_daily`, `analytics_errors`는 기존 보존 정책을 변경하지 않는다. 이들은 이메일·PDF 파일 내용 등이 아닌 집계이므로 문의 본문과 분리하여 관리한다.
- 보존을 위한 백업은 **정리 정책과 다른 별도 절차**이며 이 기능을 코드상에서 자동 운영 백업이라고 주장하지 않는다.

## B4 개발 및 검증
- `src/admin-retention.mjs`: Cron이 실행하는 읽기 쉬운 데이터 보존 함수. `src/worker.mjs`의 scheduled 핸들러가 호출.
- `tests/admin-retention-restore.cjs`: 실제 SQLite 마이그레이션 실행, 오래된 문의·변경 이력/고아 이력 제거, 최근 데이터 보존, 익명 세션·로그인 만료 확인, 두 번 실행해 멱등성 확인. **로컬 합성 데이터**를 `VACUUM INTO` 스냅샷으로 저장했다가 다시 열어 테이블 수와 `integrity_check` 비교.
- `tests/browser-admin-auth.cjs`: GitHub Linux Chromium과 **임시 로컬 SQLite**에서 실제 관리자 초기 설정 → 비밀번호 로그인 2개 브라우저 세션 → 비밀번호 변경 → 두 세션 폐기 → 새 비밀번호 로그인 → 로그아웃. 시험 전용 토큰만 사용.
- 로컬 브라우저 시험은 Cloudflare Workers 운영 D1·실제 Cloudflare 배포·도메인 인증서·운영 로그인과 동일하다고 볼 수 없다.

## 실제 운영 백업·복원 출시 체크리스트
1. 운영 D1 기존 스키마, 데이터베이스 ID, 마이그레이션 적용 이력, Worker 배포 버전 확인. **기존 0004 게시 날짜 마이그레이션은 재실행 금지**.
2. 담당자가 Cloudflare에서 지원하는 공식 D1 백업/복원 방법을 최신 문서로 확인하고, 권한 제한·암호화된 저장 위치·개인정보 보존기간을 승인.
3. 운영 DB 원본을 **변경하지 않는 방식으로** 백업하고 기록된 시각·버전·파일 해시/보관 담당자를 남긴다. 비밀값·실제 사용자 이메일이 포함된 DB 덤프를 GitHub/PR/공개 CI 로그에 올리지 않는다.
4. 운영 DB를 직접 덮어쓰지 않고, 별도의 격리된 시험 DB에 백업본을 복구해 스키마·건수·대표 조회·관리자 인증 정책을 검증한다. 필요 시 민감정보를 시험 전에 비식별화한다.
5. Worker 배포/DB 마이그레이션 전 정상 롤백 경로 및 이전 버전 호환성을 문서화한다. 복원 시험 없이 '백업 완료' 혹은 '운영 복구 검증 완료'로 표기하지 않는다.

## 완료 판정
- ADM-10: 로컬 합성 데이터 보존/복원 회귀 통과 가능. 운영 D1 백업·별도 DB 복구 리허설은 **미완료**.
- ADM-11: 실제 Linux Chromium + 로컬 SQLite 인증 전체 흐름 시험 가능. 운영 실계정·Cloudflare 도메인·Windows/Edge 실기 검증은 **미완료**.
- 관리자 전 항목 14개에 대해서는 위 운영 검증까지 끝나기 전까지 최종 수용 완료 100%를 선언하지 않는다.
